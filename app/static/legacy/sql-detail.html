Hash Join Spill Principle
Hash Join has two phases: Build phase and Probe phase. In the Build phase, data from the smaller table is loaded into an in-memory Hash Table. When the data exceeds available memory, the database must write some Hash Buckets to disk, a process called Spill, implemented through the ExecHashJoinSaveTuple() function. Frequent spill causes severe performance degradation.
Spill Performance Impact
Disk I/O is several orders of magnitude slower than memory. When spill occurs, query execution time may increase by 10-100 times. Main reasons include: 1) Serialization and deserialization overhead; 2) Disk read/write latency; 3) Multiple scans of disk data.
