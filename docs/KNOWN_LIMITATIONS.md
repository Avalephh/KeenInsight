# 已知限制与验证范围

本文件记录当前真实边界，不以文档承诺代替尚未实现的代码。

## 工作流

1. **TP 新候选与 TPS 实验未统一。** 在线告警链确实调用 LLM 并做临时参数
   应用/只读探针复测/恢复；控制台 TP 候选回放是另一输入。本发布版去掉旧
   结果文件，显式读取操作者候选。不能将两个并行发生的动作拼成一个
   “本次 LLM 提升了这次业务 TPS”的证明。
2. **DREAM 内部评估可能被再采集。** 改写后形成新 SQL 指纹时，内部评估
   SQL 仍可能被当作业务慢 SQL 再调度。它可能制造额外负载，影响计时；
   当前发布不含曾为一次测试使用的终止守护，不冒称该问题已经修复。
3. **每条 SQL 的精确单次耗时不是普遍采集能力。** 外部 workload 主要由
   pg_stat_statements 累计与轮询增量、活动字面样本提供证据。逐次精确
   数据来自受控 lab；普遍逐次记录需要应用 tracing 或日志采集补充。
4. **改写作用域有限。** bridge-managed 改写/session settings 不会自动
   拦截任意外部客户端。pg_hint_plan 对新连接的 preload 行为也需要核验。

## 安全与正确性

- 管理 API 未提供完整鉴权/RBAC、租户隔离或审批系统，只能安全地放在
  受控网络/回环地址之后。
- 参数/动作策略不是完整数据库安全证明。临时应用恢复失败需要人工
  检查原始证据；重启中断标记不等于证明全局配置已全部恢复。
- QED 未安装/不可用时，允许记录实际结果集比较路径，但那不是对所有
  未来数据的形式化等价证明。快但结果错误的查询不算成功案例。
- 模型与 LLM 输出可能出错，不能以 completed、置信度或 active 状态替代
  业务正确性/可靠性验收。

## 测量与模型

- 负载设定相同不等于实际外压相同。严格 TPS 对比需稳定基线、可比外压、
  多轮真实独立调优及误差控制。
- DREAM live adapter 没有完整的逐查询主机时序；部分模型张量通道是
  明确的缺失通道/零填充，不应声称全部多模态信号均已真实采到。
- CPU 火焰图只覆盖有限 on-CPU 窗口，不代表等待/IO/内存全分解。
- SHAP 必须有可信真实训练数据和可验证模型。本分支不带旧模型，默认
  不可用。即使加和成立也不等于模型准确或建议具备因果性。

## 部署与发布验证

- 源码检查/隔离单测不接真实 PostgreSQL、不调用付费 API、不生成压力。
  可在干净目录中执行；缺可选外部模型/参考资料明确 skip。
- 发布过程只核对本地现有功能对应的代码、目录重排后的导入、CLI、配置、
  patch 应用和源码获取；没有声称在新机器完整重装 PG、两个 Python 环境、
  所有模型并重测六组收益。
- 后续复现工具已增加独立 PG12 上的 TP fixture、AP SF1 生成/导入功能
  验证；它不是 SF10 收益、多轮真实 LLM 或全新 OS 离线安装验收。
  具体执行范围见 RELEASE_VALIDATION.md。
- 原部署形态是 PostgreSQL 12/Linux/systemd；PG13/14 与 MySQL manifest
  是参数参考适配入口，不代表在线产品已经支持并通过相同测试。
- 监控/模型依赖保持锁定版本，不应未经安全审核就公网部署或切换生产。
- 自动清理 24 小时数据与保护 active 证据并存；它不是备份系统。

后续优先项：统一 TP 新候选/TPS 闭环；隔离 DREAM 内部评估；增加部署
鉴权、逐次 SQL tracing、独立压力控制与可重复模型验证。
