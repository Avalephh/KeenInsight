# SysInsight 调优过程复现结论

## 结论

可以复现 SysInsight 的“单步分析和预测”部分；当前不能在本机现有 PostgreSQL 上安全地直接复现完整的闭环调优。

本次采用的是隔离回放：参数推荐配置取自仓库已经保存的 `OneStepTuning/onestep.json`，因此可以验证分析、匹配和预测接口，但没有让 SysInsight 修改任何真实数据库参数。

## 源码梳理

相关源码快照中，`WorkloadTune`、`WorkloadTune_new` 和 `main` 都包含同一套 SysInsight/LLAMBO/DBTune 主流程；`dev` 里另有 PostgreSQL 实验脚本，但不是当前 SysInsight 主入口。当前本地没有 git 命令，所以本次按已保存的分支快照检查，没有改动这些快照。

主流程如下：

```text
perf 采样文件 + 正常 profile
             │
             ▼
异常函数比较（采样率超出范围）
             │
             ▼
关键函数 → 关联数据库参数
             │
             ├─ 单步：LLAMBO/LLM 给出建议，预测性能变化
             │
             └─ 多步：DBTune 应用参数、重启 DB、跑工作负载、收集实测结果
```

代码中的单步入口是 `oneStepTune.py`：

- 读取当前 perf 文件、基准函数 profile、性能分数和资源快照。
- `analyze_exception()` 输出异常函数文件。
- `LLAMBO` 根据当前上下文生成候选参数。
- 单步评估函数不会压测，所有候选共享当前分数。
- 最后再次调用大模型，预测 `delta_score`，并生成推荐结果。

多步入口是 `main.py`：

- 用 MySQL 参数约束和初始值构建 LLAMBO 搜索空间。
- 每个候选通过 `DBTune()` 进入 `DBEnv`。
- `DBEnv` 会应用参数、启动工作负载并采集 TPS/延迟/QPS、资源和 perf 函数数据。

## 不能直接闭环运行的原因

1. 参数空间和默认配置是 MySQL/InnoDB 参数；当前本机运行的是 PostgreSQL 12。
2. 完整入口依赖 `openai`、`ConfigSpace`、`langchain`、`aiohttp`、数据库驱动、`dynaconf`、`paramiko` 等，当前 Python 环境没有这些依赖。
3. 原始 DBTune 会修改配置、停止/重启数据库并运行压测；不能把它指向当前正在使用的数据库。
4. PostgreSQL 适配代码仍带有 MySQL 风格连接参数和进程控制逻辑，需要单独校正后才能用于 PostgreSQL。
5. 原始 `predictMetric.py` 中包含旧接口配置和硬编码密钥，且 JSON 提取函数使用了未导入的 `re`；本目录没有复制或复用这些敏感配置。
6. 源码读取资源快照时按字典值的位置取字段，和快照字段名的语义存在错位风险；本次结果保留源码行为，未擅自修正。
