\label{sec:intro}
Modern database systems are increasingly complex, making timely diagnosis and resolution of performance anomalies a challenging task.
% In practice, database administrators (DBAs) rely on manual troubleshooting, which is costly, hard to scale across a large number of database instances, and fails to respond to incidents in a timely manner.
However, database administrators (DBAs) still rely on manual troubleshooting, which is costly, hard to scale, and often fails to respond to incidents in a timely manner.

To alleviate this burden, many semi-automated database maintenance tools have been developed.
%However, these systems still face several significant challenges.
However, existing approaches fundamentally suffer from two key limitations: they rely on \textbf{\emph{coarse-grained runtime signals}} and treat optimization as a \textbf{\emph{black-box process}}, leading to unreliable and non-interpretable decisions.
For example, observing a drop in throughput accompanied by increased I/O, existing methods may resort to trial-and-error (exploring combinations of tuning actions) or rule-of-thumb strategies, such as increasing buffer pool size. However, such actions often fail to resolve the issue, as they do not address the true root cause.
In contrast, fine-grained observability reveals frequent \texttt{log\_buffer\_flush\_to\_disk()} calls, indicating insufficient redo log buffering that triggers excessive flushes. This enables targeted optimization by increasing \texttt{innodb\_log\_buffer\_size}, effectively improving throughput.

While fine-grained execution signals are essential for understanding performance issues, collecting them (e.g., execution stacks~\cite{perf} or per-query statistics~\cite{pg_stat_statements}) incurs substantial overhead, making them impractical for continuous use in production.
Even when such signals are available, it remains challenging to translate them into actionable optimization decisions---for example, failing to recognize that frequent \texttt{log\_buffer\_flush\_to\_disk()} calls imply increasing \texttt{innodb\_log\_buffer\_size}.
This difficulty stems from the fact that the mapping from fine-grained execution behaviors to effective tuning actions is weakly supervised, highly context-dependent, and requires a deep understanding of system semantics that cannot be captured by surface-level statistics.
Existing approaches rely on small-scale learned models that are agnostic to system semantics, failing to capture the causal relationship between execution behavior and performance impact~\cite{DBLP:journals/tkde/ZhouCLS22}.
Although LLM-based approaches exhibit strong reasoning capabilities, they remain grounded in static and coarse-grained knowledge sources such as database manuals~\cite{DBLP:journals/pvldb/LaoWLWZCCTW24}, making it difficult to diagnose fine-grained runtime signals for reliable optimization.
% Besides, current approaches either optimize isolated tasks or generate recommendation-only outputs, lacking a principled mechanism to translate runtime signals into interpretable and optimization actions, and often requiring manual validation and deployment~\cite{DBLP:journals/pvldb/LaoWLWZCCTW24,DBLP:journals/pvldb/SunZLYFZ25,DBLP:journals/corr/abs-2506-23322}.

These limitations highlight a fundamental challenge: database runtime signals are both \emph{hard to collect efficiently at fine granularity} and \emph{hard to translate into reliable and interpretable tuning decisions}.
% To bridge this gap, we present \sys, an end-to-end LLM-empowered system that offers fine-grained observability with semantics-aware optimization grounded in code-level insights.
To bridge this gap, we present \sys, an end-to-end LLM-empowered system that provides fine-grained, low-overhead observability via adaptive function-level probes, and enables semantics-aware optimization grounded in deep code-level understanding.
Unlike existing approaches that rely on heuristic knowledge, \sys leverages code-driven insight by understanding database source code at the LLVM IR (Intermediate Representation) level, capturing system execution behavior and configuration propagation semantics~\cite{zhang2026manuals}.

\sys leverages eBPF (extended Berkeley Packet Filter), a lightweight in-kernel technology to enable non-intrusive collection of fine-grained database events.
To reduce overhead while preserving anomaly-critical signals, it instruments critical execution paths by adaptively attaching probes to functions indicative of performance anomalies, and employs anomaly-aware message aggregation.

\item \textbf{Hierarchical Interpretable Anomaly Diagnosis.}

\sys performs coarse-to-fine anomaly diagnosis over the streamed event flow.
Lightweight checks identify abnormal signals which trigger a diagnosis agent combining model-driven reasoning and DBA-defined rules to uncover interpretable root causes.

\sys translates fine-grained signals into tuning actions grounded in \emph{causal knowledge} derived from database source code, documentation and historical observations. It maintains feedback-driven confidence scores and validates actions before deployment.
