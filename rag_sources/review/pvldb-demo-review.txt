The authors present a very interesting, although highly complex system. The
demonstration paper itself is very technical and hard to read as many concepts are
not properly explained. The presented demo looks good but does not show real
interactivity that users at the demo booth can expect.
Given the current status of the proposal, the demonstration falls short in two
demonstration aspects. First, the demonstrating does not show that the proposed
system actually works as the entire demo appears to be a static HTML website. It is
quite unreasonable, that a live demo would show exactly the same tuning decisions
as the main paper. A live demonstration of a system where the user triggers a ﬂush-
heavy situation (maybe a large data load) where KeenInsight then recognizes the
problem and adapts, would be desirable for an interactive demo.
Second, it is not clear how users will interact with the demo. While the demo looks
very polished, there is no indication how users actually interact with the system, not
just interacting with a static HTML page.
The presented system appears to be extremely valuable for database researchers
and administrators. However, in the current state of the proposal, I don't see this
proposal to be a good ﬁt for an interactive VLDB demo session. If the system is
capable as presented, a more sophisticated use case than a ﬂush log issue and a
misplaced hash join would be very helpful. Both are typical issues that most DBAs
would check ﬁrst.
Minor:
- several parts of the system are named "on the side", while they are on their own
probably a full PVLDB research paper; it would help the paper to keep the demo
and the presented use cases simpler (example: "A scoring model trained on
historical data [6] predicts potential anomaly types (e.g., suboptimal query plans or
poorly written queries), guiding subsequent tuning decisions.")
- references: [4] misses authors
