Root Cause Explaination Related Knowledge Base
Frequent calls to HashJoinIterator::WriteBuildTableToChunkFiles() indicate that the Hash Join is experiencing a spill during execution, meaning the in-memory hash table cannot
accommodate all rows from the build side. Normally, during the Build phase of a Hash Join, data from the smaller table is stored in an in-memory hash table, and matching is
performed via memory lookups during the Probe phase. However, when the build-side table exceeds the available memory, MySQL writes some hash table partitions to disk
chunk files to free up memory, a process handled by HashJoinIterator::WriteBuildTableToChunkFiles(). Frequent spills can severely degrade performance because disk I/O is
significantly slower than memory operations, potentially increasing query execution time by an order of magnitude.
